# Deployment Guide

Order matters: **Neon → Cloudinary → Backend → Website → Flutter app**. Everything below works on free tiers.

```
Flutter app ─┐
             ├─► Backend (Render) ─► Neon (data) + Cloudinary (photos)
Website ─────┘   (Vercel)
```
Put the project in a GitHub repo first (`.env` files are git-ignored; never commit secrets).

---
## 1. Neon PostgreSQL
1. Sign up at neon.tech → **Create project** (choose the region closest to your Render region/customers).
2. On the dashboard click **Connect**, tick **Connection pooling**, and copy the string. It looks like
   `postgresql://user:pass@ep-xxx-pooler.<region>.aws.neon.tech/neondb?sslmode=require`. Keep it secret; this is your `DATABASE_URL`.
3. Create tables, either way:
   - **SQL Editor:** paste `backend/schema.sql` and run. Or
   - after the backend is configured: `python -m app.init_db`.
4. Neon's free tier suspends idle databases; the first request after a pause takes ~1 s longer. That is normal.

## 2. Cloudinary (photo storage)
1. Sign up at cloudinary.com (free). On the Dashboard copy **Cloud name, API Key, API Secret**.
2. Nothing else to configure; the backend uploads into `bakery/…` folders and stores only the URLs in Neon.

## 3. Backend on Render
1. Render → **New → Blueprint** → select your repo (it reads `render.yaml`). Or create a **Web Service** manually:
   root dir `backend`, build `pip install -r requirements.txt`,
   start `gunicorn app.main:app -k uvicorn.workers.UvicornWorker -w 2 -b 0.0.0.0:$PORT --forwarded-allow-ips="*" --timeout 120`.
2. Environment variables:

| Variable | Value |
|---|---|
| `ENVIRONMENT` | `production` (hides /docs, refuses a weak JWT secret) |
| `DATABASE_URL` | Neon pooled string from step 1 |
| `JWT_SECRET` | auto-generated by the blueprint, or `python -c "import secrets; print(secrets.token_urlsafe(64))"` |
| `ADMIN_INVITE_CODE` | any long random phrase; you'll type it once when creating the owner account |
| `CLOUDINARY_*` | the three values from step 2 |
| `CORS_ORIGINS` | your website URL(s), comma-separated, no trailing slash (set after step 4, then redeploy) |

3. Deploy. Check `https://<your-service>.onrender.com/health` → `{"status":"ok"}`.
4. Tables: if you didn't run `schema.sql`, open the Render **Shell** and run `python -m app.init_db`.

> **Free-tier note:** Render's free web services sleep after ~15 min idle; the first visit then takes 30–60 s to wake.
> For a real business use the paid Starter plan (~$7/mo), or ping `/health` every 10 min with a free uptime monitor.

## 4. Website on Vercel (or Netlify)
1. Vercel → **Add New → Project** → import repo → **Root Directory: `website`**. Framework preset: Vite (build `npm run build`, output `dist`).
2. Environment variable: `VITE_API_URL` = `https://<your-service>.onrender.com` (no trailing slash).
3. Deploy, then copy the site URL into the backend's `CORS_ORIGINS` on Render and redeploy the backend.
4. Custom domain: Vercel → Settings → Domains; then add the new domain to `CORS_ORIGINS` as well.
Page refreshes on `/cakes/...` work because of `vercel.json` (Netlify uses `public/_redirects`).

## 5. Flutter admin app
1. Follow `admin_app/README.md` (generate platform folders, add permissions, `minSdk 23`).
2. Remove `android:usesCleartextTraffic="true"` if you added it for testing.
3. Build with your live API:
   `flutter build apk --release --dart-define=API_URL=https://<your-service>.onrender.com`
4. Install `build/app/outputs/flutter-apk/app-release.apk` on the owner's phone (allow "install unknown apps"),
   or publish via Google Play with `flutter build appbundle`. Create a release keystore and **back it up**; losing it means you can't update the app.
   iOS needs an Apple Developer account (TestFlight/App Store).

## 6. First-run checklist (end-to-end test)
1. Open the app → **Create the owner account** (email, 10+ char password, bakery name, invite code). Registration then closes automatically.
2. **Bakery** tab: add logo, phone, WhatsApp number (digits with country code, e.g. `919876543210`), address, social links → Save.
3. **Website** tab: write the headline/story, pick a homepage photo → Publish changes.
4. **Cakes** → New cake → add a photo from the camera → Preview → **Save & publish**.
5. Open the website: within ~30 s the cake appears in the gallery and on the home page (featured), the WhatsApp button opens a chat with the cake name pre-filled, and the footer shows your social links.
6. Toggle the cake off in the app → it disappears from the site (direct URL returns "not found").

## 7. Security notes
Already in place: bcrypt passwords, short-lived JWTs + refresh tokens in the phone keystore, all admin routes protected and scoped to the owner, closed registration, input validation, image content verification and size limits, login rate limiting (10 failures / 15 min / IP), strict CORS, no secrets in any frontend, API docs disabled in production, generic 500 errors.

Recommended before/after launch:
- Rotate `JWT_SECRET` if it's ever exposed (this signs everyone out).
- Keep `ADMIN_INVITE_CODE` set. Registration is closed once the owner exists, but this blocks a race on first deploy.
- Neon: enable the free point-in-time history window and note your project's backup/restore options.
- Add an uptime monitor on `/health`, and use Render's log view for errors.
- Keep dependencies current (`pip list --outdated`, `npm outdated`, `flutter pub outdated`).

## 8. Troubleshooting
| Symptom | Fix |
|---|---|
| Website shows "We'll be right back" | `VITE_API_URL` wrong, backend asleep (retry in a minute), or site URL missing from `CORS_ORIGINS` (browser console shows a CORS error) |
| App says "Cannot reach the server" | Wrong `API_URL` at build time; on emulator use `10.0.2.2`, on a phone the computer's LAN IP or the https URL |
| Photo upload fails with 502 | Cloudinary keys wrong or missing on Render |
| Photo upload fails with 422 | File isn't JPEG/PNG/WEBP (e.g. HEIC), or over 8 MB |
| 429 "Too many attempts" | Wait 15 minutes, or restart the Render service |
| Cake saved but not on the site | It's still a draft (switch it to Live), or wait ~30 s for the cache |
| `sslmode` / connection errors | Use the Neon string with `?sslmode=require`; prefer the **pooled** host |
| Android build: "minSdkVersion" error | Set `minSdk = 23` in `android/app/build.gradle` |
